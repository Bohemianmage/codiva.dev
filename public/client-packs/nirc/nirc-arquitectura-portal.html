1. Resumen ejecutivo

NIRC es un ecosistema de workforce management temporal: ATS y pool con scoring por afinidad, auto-convocatoria FCFS, operación con QR, cumplimiento (IMSS / adhesión en entrada / Cincel), dispersión Stripe, contabilidad y backoffice unificado.

Flujo núcleo (actualizado):

Vacante → Aplicaciones → Pool (score por labor / afinidad)
  → Convocatoria auto (criterios) → Ofertas FCFS → Confirmado + QR
  → Check-in QR → INE → Contrato adhesión (ENTRADA) → Alta IDSE PRO
  → Check-out → Baja IDSE + Stripe → Contabilidad → Disposal
Backoffice: vacantes · aplicaciones · pools · validaciones · convocatorias · finanzas
IMSS: adapter IDSE PRO (docs Apimarket). Contrato de adhesión: se firma a la entrada, no a la salida. Check-in: QR en zona de trabajo + geocerca.

2. Arquitectura de plataforma

Principios

  1. Dominios desacoplados - CRM/ATS, Operación, Cumplimiento, Finanzas.
  2. Orquestación por eventos y colas - no acoplar IMSS/Cincel/Stripe al request HTTP del check-in.
  3. Adapter IMSS = IDSE PRO - proveedor ApiMarket/Codiva.
  4. Inmutabilidad contable y de auditoría - solo reversas.
  5. PWA operativa - admin de sitio y flujos de personal.

Gates

  1. QR/check-in - asignación + geocerca + token
  2. Contrato adhesión - firma en entrada
  3. Alta IDSE - tras contrato + merge candidato/patrón
  4. Check-out - baja + Stripe (sin contrato)
  5. Disposal LFPDPPP - retención / borrado

8. Pool scoring y auto-convocatoria FCFS

flowchart LR V[Vacante] --> A[Aplicaciones] A --> P[Pool] P --> S[Score por labor] S --> C[Criterios convocatoria] C --> B[Auto-blast] B --> F[FCFS acepta] F --> Q[QR + entrada]

El pool se puntúa por afinidad a cada labor (skills, historial, performance, zona, docs IDSE-ready, features contextuales). Al publicar criterios se dispara el blast; la aceptación es first come, first served con reserva atómica de cupo y TTL de oferta.

9. Contabilidad, LFPDPPP y seguridad

flowchart TD CI[Check-in / Alta] --> A1[Asiento provisional\nCosto operativo / CxP] CS[Contrato firmado] --> A2[Confirma CxP] PY[Stripe paid] --> A3[Cargo CxP · Abono Banco] FL[Payment failed] --> A4[No cierra · alerta] A1 --> AUD[audit_logs + UUID] A2 --> AUD A3 --> AUD

LFPDPPP - uso y disposal

  • Consentimiento al aplicar y al firmar adhesión; geolocalización al emitir/usar QR.
  • Minimización: a IDSE solo campos del movimiento; biometría con retención mínima.
  • Jobs privacy.retention / privacy.dispose tras descartes y cierres.
  • Acuses IMSS y contratos firmados: retención legal; resto anonimizar/borrar al vencer.

Seguridad

  • TLS en tránsito; cifrado en reposo para PII y documentos.
  • QR: token opaco firmado, TTL, un solo uso, sin PII en claro.
  • Certificados IMSS / e.firma: responsabilidad del cliente; alertas de vencimiento.
  • Auditoría de check-in/out: usuario, IP, GPS, timestamp.
